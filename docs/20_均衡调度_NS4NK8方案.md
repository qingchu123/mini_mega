# 20 均衡调度方案：NS=4 × NK=8 轮询 + split-K

> 目标：消除 **rank 内本地专家负载不均衡** 导致的空转/长尾。
> 手段：把每个（非空）专家切成 **NS×NK = 4×8 = 32 个等代价任务**，用 **轮询映射**
> 让每个 AP 在每个专家上各领 1 个任务 → 每 AP 总工作量恒等 = `W/P`，零长尾。
> 落地：`agent/r19balance/*` 分支；门禁 = `scripts/run.sh check --smoke`。

---

## 1. 问题回顾

- 现在：任务 = `(专家 e, 窗口 w, slice s)`，`win` 自适应；`dispatch_pull_body` 用
  **动态 FCFS 领号**（`atomicAdd(task_counter)`）。
- rank 内 8 个专家的 token 数 `c_e` 差异大 → 每专家窗口数 `ceil(c_e/win)` 差异大。
- FCFS 按**任务个数**发牌，但任务代价 ∝ `c_e`（同一专家内窗口满行）→ 慢 AP 拖尾：
  `makespan ≈ W/P + max_task`。
- 且 `total_tasks ≤ grid` 时走**静态单波**（`if(...) break`），完全不偷活 → 小 TPR 更不均衡。

## 2. 均衡原理（为什么轮询 = 零长尾）

设每专家切成 `M = NS×NK` 个**等代价**任务（同一专家内代价 = `f(c_e)`，与槽 i 无关），
AP 数 `P = M`，映射 `(专家 e, 槽 i) → AP i`（轮询）。则

```
AP i 的总工作量 = Σ_e f(c_e) = W / P     （与 i 无关）
```

**每个 AP 的总量完全相同 → 同时开工、同时收工 → 零空转**。`c_e` 再偏也不影响，
因为偏的是"每轮长度"，而所有 AP 都分摊了每一轮。这是调度下界 `W/P` 的可达构造
（等代价 + 轮询 = 完美均衡）。

**关键要求**：
1. `每专家任务数 = NS×NK = P`（本方案 `4×8 = 32`）；
2. 同专家内所有任务**等代价**（同 `c_e`、同 N/K 子块）；
3. **映射必须是轮询/strided**（`task(e,slot) → block = slot`），不能 FCFS。

## 3. 为什么必须 K 切分（而不是只切 N）

`win=512(=max_tokens)` 时每个专家恰 **1 个窗口**，只切 N 得 `NS=4` 个任务/专家，
无法填满 `P=32`（一个专家只占 4 个 AP → 其余 28 空）。要 `NS×NK=32` 就必须
**K 切 NK=8**。

三种切分对访存的影响（决定代价）：

| 切法 | A 读 | 权重读 | 任务代价 | 归约 |
|---|---|---|---|---|
| N (=NS) | ×NS 重复 | 不重复 | ∝c_e | 否 |
| M (=行) | 不重复 | ×份数重复 | 均匀 | 否 |
| **K (=NK)** | 不重复 | **不重复** | ∝c_e | **FP32** |

→ **只有 K 切分不放大 A/权重访存**，代价是"gate/up 的 FP32 部分和归约"。

## 4. 设计

### 4.1 任务与映射
- 任务 = `(e, s, c)`，`s∈[0,NS)`、`c∈[0,NK)`；`slot = s*NK + c ∈ [0, P)`；`P = NS*NK`。
- **静态轮询**：`block b` 处理槽 `b`，专家按 `e = 0,1,...,EPR-1` 依次推进（跨专家按需 fencing）。
- 空专家（`c_e=0`）跳过；仍保持"每 AP 每专家 1 任务"。

### 4.2 L1 split-K（核心）
- 每个 `(e,s,c)` 任务：对窗口 `c_e` 行的 **A[:, kchunk] × W1[kchunk, Nslice_s]** 做 MMA，
  得到 **FP32 gate/up 部分和** `part[slot][rows][2I/NS]`（`atomicAdd` 累加）。
- 每个 `(e,s)` 的一组 NK 个任务由 **atomic 计数器** 记录完成数；**最后一个** chunk
  读出累加结果 → **SwiGLU → FP8 量化** → 写 `ffn_hidden`，随后发布 `l1_prog`（协议不变）。
- `kchunk`：`c*(H/NK)` 起、长 `H/NK`（H=6144、NK=8 → 768）。

### 4.3 其余相位不变
- `l1_prog` wait-all（NS 个 slice 齐）→ L2（`r24_l2_big`）→ `tail`/COMBINE → `l2_done`、
  REDUCE —— 与现行逐字一致，仅 L1 前置换成 split-K 化。

### 4.4 资源与开销（关键风险）
- **FP32 部分和缓冲**：每 `(e,w%ring,s)` 槽 = `win×2I/NS×4B`（512×1024×4 = **2MB**）。
  在飞槽 = `EPR×ring×NS = 8×8×4 = 256` → **上限 ~512MB**（按 ring 复用；HBM 足够）。
- **归约开销**：参考 `test/94`，NK=8 时约 **10~14%**（部分和写+读，非 A/权重）。
- **同步**：NK 组 atomic 计数 + 一个 fencing；窗口内 NS 的 wait-all 耦合点不变。

### 4.5 正确性要点
- SwiGLU 非线性 → **必须先 FP32 累加 gate/up 再 SwiGLU**（不能对量化后相加）。
- 数值等价：FP32 累加顺序与单块 K 循环不同 → 非 bit-exact，但在容差内（smoke 需过）。
- `l1_prog` 必须在**归约完成之后**发布（否则 L2 读到未累加完的 ffn_hidden）。

## 5. 验证计划
1. 编译 + `check --smoke`（8 用例，含 graph×50）。
2. `mybench -s1`（TPR 16..256）与基线 A/B；目标不回退 >5%。
3. `MXKERNEL_COUNT=1` 看 `kCtrTasksPerBlockMax/Min`（应 max=min，验证均衡）。
