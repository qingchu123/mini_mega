# 10 设备端动态窗口（auto window）高性能方案

> 状态：实现方案（承接 docs/06 第 3 版）。目标：把窗口容量 `win` 从 host 决策搬进
> kernel，逐 launch 由设备端按全局专家计数 `s_count[e]` 选取，使 CUDA graph replay
> 也能自适应（host 在 capture 内无法同步）。本文给出精确改动点与分阶段计划。

## 1. 核心思路（高性能 + graph-safe）

**解耦"行 stride / 模板上界"与"运行期窗口"**：

- host 只传一个与负载无关的**上界** `cap_hint`（= 物理容量，来自 `slot_capacity`
  或配置的 `win_phys`）。所有**行 stride、模板实例、smem** 仍由 `cap_hint` 决定 →
  capture 时固定，graph 合法。
- 设备端在 `[win_min, cap_hint]` 内选一个候选 `win`，**只用于窗口划分**（每个专家
  按 `win` 切窗、`count = min(remain, win)`）。
- 因为 `win ≤ cap_hint`，任一窗口的行数 ≤ cap_hint，落在已分配的 stride 内；多余行
  不用，但布局一致 → MEGA / COMBINE / REDUCE 三方 stride 恒等于 `cap_hint`，无需
  运行期协商。

这样：设备端选窗是**纯计算**（EPR 次除法），无 host 同步，replay 自适应。

## 2. 现状依赖（为什么不能直接改 win）

`win_cap` 当前同时承担 4 个角色（`src/kernel.cuh:34`）：

| 角色 | 位置 |
|---|---|
| 窗口划分（每专家窗数） | `compute.cuh:934`、`compute.cuh:1069-1071` |
| pool 行 stride | `MegaArgs.pool_stride = win_cap`（`mega.hpp:249`）|
| staging 行 stride | `tail.ctx.staging_cap = a.win_cap`（`kernel.cuh:257/277`）|
| ffn_hidden / l2_out stride | `kernel.cuh:63-64` |
| 编译期 count 上界实例 | `megakernel.cu:169-181`（kCap=48/64）|
| smem 尺寸 | host `prod_smem(R,8,win_cap)`（`mega_common.cuh`）|

**关键**：只要把"划分用的 win"与"stride/模板/smem 用的 cap_hint"分开，前三行 stride
都固定为 `cap_hint`（负载无关），设备端只改划分。这就是本方案的最小面。

## 3. 选择算法（设备端，廉价）

代价模型（docs/07 §3，merge 已去 m=1，N=kNSlice=4，G=kGrid=32）：

```
W(win)   = Σ_e ceil(c_e / win)              // 窗口数
T̂(win)   = ceil(W(win)·N / G) · (T_FIX + N·A·win)   // 定点整数，host/device 一致
win*     = argmin_{win ∈ 候选, win_min≤win≤cap_hint} T̂(win)
```

- `c_e = s_count[e]`（所有 rank 一致，`prologue.cuh:409-412`）。
- 候选集合 `C = {32,48,64,128}`（docs/06 §2；可再收窄）。
- `T_FIX`、`A` 为待标定常数（定点整数，避免 host/device 浮点差异）。
- 计算量：`|C|·E` 次整数除法 ≈ 32 次，每 rank 纳秒级。

**标定**：按 launch 对 `C` 各测一次耗时；用 `(W(win), T)` 拟合 `T_FIX, A`，使 `T̂`
的 argmin 与逐 launch 实测最优一致（docs/06 §7）。标定数据放 `docs/`。

## 4. 精确改动点（实现阶段）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `src/win_select.cuh`（新） | `__host__ __device__ select_win(counts, E, cap_hint, win_min)` + `win_cost`，候选集合与常数 |
| 2 | `src/kernel.cuh` | `MegaArgs` 增 `win_min`（或复用常量）；`pool_stride/staging` 语义改为"=cap_hint" |
| 3 | `src/prologue.cuh` `task_setup_body` | block0 在读完 `s_recv` 后：算 `win=select_win(...)` → 用 `win` 建窗表；写 `lf->win_sel`；其余 block 经 task_ready 后读 `win_sel` |
| 4 | `src/compute.cuh:928-934,1069-1071` | 窗表/`s_count_w`/`s_row_off` 用运行期 `win`（从 lf 读），不再用 `win_cap` |

## 5. 分阶段计划

1. **Phase 0 标定**：新 harness，按 launch 对候选各测耗时，拟合 `T_FIX, A`；产出
   `docs/` 标定表 + `win_select.cuh` 常数。验证：`T̂` 排序 vs 实测。
2. **Phase 1 选择器**：实现 `win_select.cuh`；host 参考实现与设备端在随机 `s_count`
   上逐值一致（单元测试）。
3. **Phase 2 解耦接入**：改 §4 的 stride/模板/smem 语义为 `cap_hint`；task_setup 计算
   `win_sel`；compute 用运行期 win。验证：check smoke/子集/top50、eager==graph。
4. **Phase 3 对照**：设备端选择 vs 固定 win=64（top50 + 独立负载），确认不劣。

## 6. 风险

- **标定过拟合**（docs/06 §8.1）：需独立负载验证。
- **收益不确定**：逐 launch 最优 vs 固定 64 若收益 <2%，复杂度不值（docs/06 §8.2）。
- **stride 固定为 cap_hint** 会增大常驻显存（pool/ffn/l2 按上界）；需确认 `cap_hint`
  取值（建议 ≤128，`win_phys` 选择见 docs/06 §5）。
- **模板实例**：`cap_hint` 大则失掉 kCap=48/64 裁剪；需权衡实例数与上界。
- **守卫**：设备端不能 `exit(2)`，靠钳制 `win∈[win_min,cap_hint]` 保证合法。
