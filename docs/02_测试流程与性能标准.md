## 1. 性能口径（唯一正式口径）

> 原文：`empty_kernel_bench.cu:3120-3122` —— “单张 graph 内 N 个同构节点；host 只发 1 次/replay；
> per-kernel = 总时间/(N*M)。**这是本项目唯一允许的性能口径**。”

### 1.1 定义（`graph_chain_measure`，`empty_kernel_bench.cu:3123-3169`）

| 项 | 规定 |
|---|---|
| 图结构 | 单张 CUDA Graph，内含 **N 个同构节点**（N = `--nodes`，空 kernel 基准用 2000，其余相位用 100~1000） |
| 提交方式 | 每个 replay **host 只提交 1 次**（`mcGraphLaunch`），节点间无 host 介入 |
| 测量方式 | 每个 replay 用**独立 event 对**（`c0[i]`/`c1[i]`）夹住，`mcEventElapsedTime` 取该 replay 总时间 |
| 换算 | `per-kernel = replay 时间 / nodes` |
| 预热 | **预热 2 次**，不入测量 |
| 采样 | **5 次 replay**，取**最小值（min-of-5）**，不是中位/均值 |
| 对齐 | 预热后、每次 replay 前做一次跨 rank 线程 barrier（`rank_barrier()`，落在 event 窗口**之外**，不改计时语义，消除主机提交偏斜累积） |
| 自检 | graph 执行自检：`epoch_ctr` 增量必须等于 `(2+5)×nodes×2`（2 次预热 + 5 次测量，每次每节点 epoch 步进 2）；不满足即 FAIL（`empty_kernel_bench.cu:4008-4018`） |
| 输出 | `[phase]`/`[结论-B]`/`[结论-C]` 行，单位 µs/kernel |

### 1.2 为什么不用 host wall / 单次 event

1. **host wall 含提交间隙**：多 rank 多线程下 host 提交偏斜与调度抖动会被计入；graph 链只发 1 次/replay，host 空隙落在 event 窗口之外。
2. **单次 event 噪声大**：共享机器上其它租户的间歇干扰会污染单次采样。
3. **min-of-5 的目的**：过滤间歇性干扰；同会话 A/B 对比公平（中位会被干扰 replay 污染）。
4. **rank_barrier 的目的**：防止 8 个 rank 的 replay 起点漂移累积触发 kernel 内跨 rank 等待超时；它在 event 窗口外，不改变 per-kernel 计时语义。
5. 骨架另有分相计时（`phase_ticks`，`clock64()`）用于定位瓶颈：折算频率固定 **2000MHz（XCORE_CLK，mx-smi）**；用 device attribute 的 1600MHz 会把所有相位高估 25%（results.md §7.3）。分相只是**诊断口径**，正式性能只认 graph 链。

### 1.3 会话波动与比较规则

- 数值随会话/机器负载波动（例：完整前序 R=32 在 25.3~34.6µs 间波动，results.md §6、§8）。
- **跨会话数值不直接对比**；A/B 优化必须在同一会话内跑对照链。
- 骨架约定：相位对比以“单独相位”为准，含 drain 等待的组合项（如 prelude+setup）波动大（results.md §6 注）。

## 2. 正确性协议

### 2.1 三形态路由（`make_routes`，`empty_kernel_bench.cu:2636-2674`）

| 形态 | `--pattern` | 生成规则 | 覆盖点 |
|---|---|---|---|
| balanced | 0 | `out[i] = (i + rank*kEPR + salt) % E`，`E=R*EPR`，`n=tokens*topk=128` | 每专家恰好 16 对；正式计时唯一形态 |
| hot | 1 | `out[i] = (i%4!=3) ? 0 : (1 + (i/4 + rank*3 + salt)%(E-1))` | 3/4 路由压向专家 0 → 超容量截断、多窗口长尾、ring 门 |
| mixed-invalid | 2 | LCG 随机；10% 概率 `-1`（非法 ID），其余 `% E` | 非法 ID 跳过、重复路由、按容量截断 |

- **balanced 必须自检**：新增 `[balanced 分布]` 行（每专家路由对数 min/max == 16，否则 FAIL）。
  历史 bug：`(i+rank)%E` 在 `n=128 < E=R*8` 时分布不均（R=32 时 rank20~31 收 0 对），
  曾造成“R=32 L1 变慢 2×”的错误归因（results.md §7.0、§9.5）。修复为步长 `kEPR`。
- hot 形态 R=32 的 N1 链约 38ms/节点，**不用于正式计时**，只用 ns=3 做正确性（`run.sh` 注释）。

### 2.2 CPU 参考与行级校验（全 rank、全量）

| 相位 | 校验内容 | 判定 |
|---|---|---|
| ROUTE | `route_slot_counts[e]==min(sent[e],cap)`；行内槽序不要求，必须是该 (le,src) pair 集合的**互异子集**且不越界，其余槽为 0 | 全 PASS |
| PUBLISH | `recv[src][le]==min(...)`；行尾校验槽满足 `Σ+epoch == ~csum` | 全 PASS |
| XBAR 可见性 | prelude 后 block0 各 lane 读本 rank 收到的 `expert_recv_counts` 行自旋校验 `Σ+epoch==~csum` | 全 PASS，timeout=0 |
| TASK_SETUP | 前缀表全表、每 block 总窗口数 `Σ_e ceil(cnt_e/cap)`、`task_ready` 推进 | 全 PASS |
| DISPATCH | 首波任务用 host 模型精确校验 pool payload 字节（x 视图确定性模式）、weights、metadata；槽复用只校验**每个专家最后一个窗口**（`w+ring` 会覆盖早期槽）；staging 仅单波确定 | 全 PASS |
| L1 | 校验和防 DCE + 非零检查；**串行 vs 流水逐位对照**（相对差 0.0e+00）；各变体（n4/n4宽/packed/配对）与基准校验和逐位一致 | 全 PASS |
| L2 | **CPU 参考对比**：block0 的 16 行 × K=2048 在 host 做 FP8(E4M3)→FP32 乘加（256 项查表解码，B 按 lane 序 tile 解析），相对误差 <1e-2 | PASS |
| COMBINE | **抽查**：rank0 block0 首个有效行，按 meta 定位目标 rank/行，与 `ffn_out` 逐元素对比 `max_err=0.0` | PASS |
| REDUCE | **全量**：rank0 全量 `y` vs CPU 参考（`combine_rows × topk_weights` 求和）`max_rel=0.0` | PASS |

- 正确性段用**单次 launch + 全 rank join**，不是 graph 链。
- 骨架输出行样例：
  `[正确性] balanced R=8 route=PASS publish=PASS xbar=PASS task_setup=PASS dispatch=PASS n4=... 校验和相对差=0.0e+00/...`

### 2.3 `--stress N` 长稳压测

- 语义（`empty_kernel_bench.cu:3716-3948`）：共 N 轮，每轮 `pattern = spats[it%3]` 轮转（balanced/hot/mixed-invalid）
  且 `salt=轮号`（每轮路由不同），跑完整前序 `route+publish+xbar+setup`，对全部 rank 做四项全量校验
  （route / publish / xbar 可见性 / task_setup 前缀+窗口数+task_ready），统计失败轮数。
- **用途**：任何“去掉/替换 checksum、改可见性协议、改 barrier”的方案，必须过 `--stress` 长稳。
- **判定门（对照门）**：checksum on 时必须 **0/N 失败**；checksum off 的失败率用于证明校验不可省。

| 配置 | 轮数 | 失败 | 首败信息（results.md §6.1） |
|---|---:|---:|---|
| R=8，checksum off | 300 | **290** | `task_setup: block1 total=11 want 8` |
| R=8，checksum on（对照） | 300 | 0 | — |
| R=2，checksum off（会话 A） | 300 | 0 | — |
| R=2，checksum off（会话 B） | 300 | **273** | `task_setup: block1 total=9 want 8` |
| R=2，checksum on（对照） | 300 | 0 | — |
| R=32，checksum off | 100 | 0 | — |

> 结论：**checksum 不可省**；短跑通过不代表安全（R=2 两次会话一次 0/300、一次 273/300）。
> 任何省 checksum 的方案只能走 S5（metadata 移普通显存 + release/acquire 重建可见性），
> 且验收必须用 `--stress` 且 checksum on 对照 0 失败（results.md §6.1、§11.1）。

## 3. 运行规则（硬约束）

来源：`results.md §7.11`、`ai_rules.txt`、`remote_test.sh`、`AGENTS.md`。

| # | 规则 | 落地方式 |
|---|---|---|
| 1 | **单次测试 ≤20s**，自动超时退出；超时的测试需要优化 | `timeout 20`（`remote_test.sh:14` 的 `T=20`）；超时 rc≠0 视为失败 |
| 2 | 运行必须加 **`stdbuf -oL`**（否则日志不落盘） | 所有 bench 命令前缀 `stdbuf -oL`（`AGENTS.md` 运行环境） |
| 3 | 8 卡测试**固定用最后 8 张卡** | `MACA_VISIBLE_DEVICES=24,25,26,27,28,29,30,31`（已验证进程落在 GPU 24-31） |
| 4 | **双机并行**：本机 `10.0.82.202` 或 `lchen1@10.0.82.71`（免密）；**任一 PASS 即通过** | `remote_test.sh`：rsync 代码 → 两侧并行执行 → `grep -c "OVERALL=PASS"`，任一侧 >0 即 PASS；远程 ssh 用 `timeout $((T+10))` |
| 5 | 测试模式开关（解决 ≤20s） | `--perf-only 1`：跳过正确性校验段（保留路由上传与全部计时链）；`--quick 1`：跳过对照链（N1/N8/N16/N16p）。组合实测 71 机 **~2s**（results.md §7.11）。注意：骨架最新 .cu 已把两开关接入参数表（`empty_kernel_bench.cu:3357-3358`），新工程应实现为真实门控 |
| 6 | 总判定 | 程序末尾 `OVERALL=PASS/FAIL`（`all_ok = audit_ok && sync_ok && graph_ok && route_ok`，`empty_kernel_bench.cu:4320-4327`）；退出码 0/1 |

> 新工程注意：`task.txt` 对**单元 kernel 自测**要求 **≤10s**（比骨架 20s 更严）；
> 建议：单元测试用 10s 门，集成/双机用 20s 门，两者都加 `timeout`。

### 3.1 `remote_test.sh` 机制要点（`remote_test.sh:1-51`）

1. `rsync -az` 同步整个仓库到远程（19MB，秒级）。
2. 本机与远程**同时**执行同一命令；本机与远程各自 `timeout T`（远程外层 ssh 再 `timeout T+10`）。
3. 两侧输出写入临时文件；`pass_l`/`pass_r` 统计 `OVERALL=PASS` 出现次数。
4. 任一 >0 → 输出“PASS（任一通过即可）”并打印通过侧关键结论（exit 0）；否则打印两侧尾部日志（exit 1）。

### 6.1 `build.sh`（宿主机 cucc + mcr runtime，无需容器；原样保留）

```bash
#!/usr/bin/env bash
# 宿主机编译（cucc + mcr runtime，无需容器）
set -euo pipefail
cd "$(dirname "$0")"
REPO="$(cd ../../../../../.. && pwd)"
export MACA_PATH=${MACA_PATH:-/opt/maca}
export CUDA_HOME=${CUDA_HOME:-$MACA_PATH/tools/cu-bridge}
mkdir -p "$HOME/_nvcc"
"$MACA_PATH/tools/cu-bridge/bin/cucc" -O3 -std=c++17 \
  -I"$MACA_PATH/tools/cu-bridge/include" \
  -I/opt/maca/include \
  -I"$REPO/mxmegakernel/include" \
  -o empty_kernel_bench empty_kernel_bench.cu
echo "built: $PWD/empty_kernel_bench"
```

环境变量：`MACA_PATH`（默认 `/opt/maca`）、`CUDA_HOME`（默认 `$MACA_PATH/tools/cu-bridge`）。
编译产物：同目录 `empty_kernel_bench`。

### 6.2 `run.sh`（依次跑 R=2/8/32；原样保留）

```bash
#!/usr/bin/env bash
# 依次跑 R=2/8/32；性能一律 CUDA Graph 链口径。
# 注意：正式计时只跑 balanced（--pattern 0）——hot 形态在 R=32 的 N1 链约 38ms/节点，
# ns=2000 时单条链要 ~9 分钟且没有额外结论；三形态正确性用 ns=3 单独跑。
set -uo pipefail
cd "$(dirname "$0")"
NODES=${NODES:-100}
MAXTOK=${MAXTOK:-16}
SKEW=${SKEW:-0}
for R in 2 8 32; do
  echo "======== R=${R} 正确性(三形态, ns=3) $(date '+%F %T') ========" | tee -a "raw_r${R}_routefix.log"
  stdbuf -oL ./empty_kernel_bench \
    --ranks "$R" --max-tokens "$MAXTOK" --window 8 --bn 256 \
    --nodes 3 --tokens 16 --skew "$SKEW" --audit 0 --graph 0 --sync 0 2>&1 \
    | tee -a "raw_r${R}_routefix.log"
  echo "======== R=${R} 计时(balanced, ns=${NODES}) $(date '+%F %T') ========" | tee -a "raw_r${R}_routefix.log"
  stdbuf -oL ./empty_kernel_bench \
    --ranks "$R" --max-tokens "$MAXTOK" --window 8 --bn 256 \
    --nodes "$NODES" --tokens 16 --skew "$SKEW" --pattern 0 2>&1 \
    | tee -a "raw_r${R}_routefix.log"
done
```

### 6.3 `remote_test.sh`（双机并行；原样保留）

```bash
#!/usr/bin/env bash
# 双服务器并行测试：本机(10.0.82.202) + lchen1@10.0.82.71 同时跑同一测试，
# 任一 PASS 即通过；单次测试 20s 自动超时（规则 3/4）。
# 用法：./remote_test.sh [测试参数...]   默认参数见下方 DEF_ARGS。
set -uo pipefail
cd "$(dirname "$0")"

DIR="$PWD"
REMOTE=lchen1@10.0.82.71
REPO_ROOT="$(cd ../../../../../.. && pwd)"
DEF_ARGS="--ranks 8 --max-tokens 16 --window 8 --bn 256 --nodes 5 --tokens 16 --audit 0 --route 1 --pattern 0 --perf-only 1 --quick 1"
ARGS="${*:-$DEF_ARGS}"
GPUS="24,25,26,27,28,29,30,31"   # 规则 2：固定最后 8 卡
T=20                              # 规则 3：单次测试 ≤20s

# 同步代码到远程（19MB，秒级）
rsync -az -e "ssh -o StrictHostKeyChecking=no" "$REPO_ROOT/" \
    "$REMOTE:$REPO_ROOT/" >/dev/null 2>&1

OUT_L=$(mktemp); OUT_R=$(mktemp)
( cd "$DIR" && MACA_VISIBLE_DEVICES="$GPUS" timeout "$T" \
      stdbuf -oL ./empty_kernel_bench $ARGS >"$OUT_L" 2>&1; echo $? >"$OUT_L.rc" ) &
( timeout $((T + 10)) ssh -o StrictHostKeyChecking=no "$REMOTE" \
      "cd '$DIR' && MACA_VISIBLE_DEVICES='$GPUS' timeout $T \
       stdbuf -oL ./empty_kernel_bench $ARGS" >"$OUT_R" 2>&1; echo $? >"$OUT_R.rc" ) &
wait

pass_l=$(grep -c "OVERALL=PASS" "$OUT_L" 2>/dev/null || true)
pass_r=$(grep -c "OVERALL=PASS" "$OUT_R" 2>/dev/null || true)
rc_l=$(cat "$OUT_L.rc" 2>/dev/null || echo 1)
rc_r=$(cat "$OUT_R.rc" 2>/dev/null || echo 1)

echo "==== 双机并行测试 ===="
echo "参数: $ARGS"
echo "本机(202):   rc=$rc_l PASS=$pass_l  $(grep -m1 'OVERALL' "$OUT_L" 2>/dev/null || echo '(无结论/超时)')"
echo "远程(71):    rc=$rc_r PASS=$pass_r  $(grep -m1 'OVERALL' "$OUT_R" 2>/dev/null || echo '(无结论/超时)')"

if [ "$pass_l" -gt 0 ] || [ "$pass_r" -gt 0 ]; then
    echo "结果: PASS（任一通过即可）"
    echo "---- 通过侧关键结论 ----"
    [ "$pass_l" -gt 0 ] && grep -E "OVERALL|正确性\] |\+L1 生产式配对|生产式 N 组配对|L2（独立|REDUCE（独立|COMBINE 纯写|COMBINE 读\+打包|\+L2 全链|分相 全链" "$OUT_L" | head -12
    [ "$pass_l" -eq 0 ] && [ "$pass_r" -gt 0 ] && grep -E "OVERALL|正确性\] |\+L1 生产式配对|生产式 N 组配对|L2（独立|REDUCE（独立|COMBINE 纯写|COMBINE 读\+打包|\+L2 全链|分相 全链" "$OUT_R" | head -12
    echo "日志: $OUT_L / $OUT_R"
    exit 0
else
    echo "结果: FAIL（两侧均未通过）"
    echo "---- 本机尾部 ----"; tail -5 "$OUT_L"
    echo "---- 远程尾部 ----"; tail -5 "$OUT_R"
    echo "日志: $OUT_L / $OUT_R"
    exit 1
fi
```

### 6.5 命令行参数全表（`empty_kernel_bench.cu:3350-3370`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `--ranks N` | 2 | rank 数，只接受 2/8/32 |
| `--max-tokens N` | 16 | 每 rank token 容量（x 视图/src_index_table/recv 容量） |
| `--window N` | 8 | ring 窗口数 |
| `--bn 512\|256\|128` | 256 | block_n（生产几何） |
| `--nodes N` | 2000 | graph 内同构节点数 |
| `--tokens N` | 16 | ROUTE_BUILD 输入 token 数（≤ max_tokens） |
| `--audit 0\|1` | 1 | 显存分配一致性审计 |
| `--perf-only 0\|1` | 0 | 跳过正确性校验段（≤20s 规则） |
| `--quick 0\|1` | 0 | 跳过对照链 N1/N8/N16 等（N1 单链 ~15.8s） |
| `--graph 0\|1` | 1 | 空 kernel graph 基准 |
| `--route 0\|1` | 1 | ROUTE_BUILD 相位 |
| `--sync 0\|1` | 1 | XBAR 变体对照（仅显式 `--xbar-mode` 时跑） |
| `--xbar-mode N` | -1 | 只跑指定 barrier 变体（0~4） |
| `--skew 0\|1` | 0 | rank 不均衡场景（token 数 1..N 线性升） |
| `--no-checksum 0\|1` | 0 | 关闭 TASK_SETUP checksum（仅 A/B 量化，不作默认） |
| `--stress N` | 0 | 功能压测轮数（每轮变路由 + 全量校验） |
| `--recv-pad 0\|1` | 0 | recv 行填充到 256B（A/B 实验） |
| `--ck-variant N` | 0 | 0=基线 1=`__ldcv` 2=写入侧 fence 4=tag（不安全，禁用） |
| `--pattern N` | -1 | 只跑指定路由形态（0 balanced/1 hot/2 mixed-invalid） |
| `--win-cap N` | -1 | 窗口容量；-1=与 max_tokens 相同，0=auto `min(max_tokens,64)` 上取整 16 |
| `--win-pad N` | 0 | pool 槽 padding（新布局默认 8，避开缓存 set 冲突） |

## 附：关键结论速查（新工程必须继承）

1. **性能只认 CUDA Graph 链（min-of-5）**；host wall 与单次 event 不作为依据（§1）。
2. **checksum 不可省**（`--stress` 对照：off 可 290/300 失败）；省校验必须重建 release/acquire 协议并过压测（§2.3）。
3. **balanced 路由生成器必须用 `(i + rank*kEPR) % E`**，并输出 `[balanced 分布]` 自检（§2.1）。
4. **正式计时只跑 balanced**（`--pattern 0`）；hot 只做正确性（R=32 N1 链 ~38ms/节点）。
5. **运行硬约束**：≤20s（单元测试 ≤10s）、`stdbuf -oL`、最后 8 卡、双机任一 PASS（§3）。
6. **基线数据**见 §5；跨会话不比较，A/B 同会话；分相计时固定 2000MHz 折算（§1.2、§5）。
7. **L1 的两个必要设计**：N 组配对（A 共享）+ lane 序 packed tile（零 shuffle）——骨架证明这是 3× 差异的来源（results.md §7.5）。
8. **多轮/WS 是唯一能进 <400µs 的路径**（341.4µs/轮），但私有内存 5KB/线程 > 4KB 上限导致链测量异常，新工程需从容器设计上解决（results.md §7.18）。
