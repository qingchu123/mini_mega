# Mega Kernel 缓冲区与竞争分析

范围：`src/megakernel.{h,cu}`、`src/*.cuh`、`include/deep_gemm/layout/mega_moe.cuh`、
`test/mega_common.cuh`。所有 Agent 输出使用中文。

## 1. 缓冲区总览

### 1.1 对称区 `sym`（mcExtMallocWithFlags FG / mcMalloc 回退，IPC 共享）

| topk_weights | `mb.input_topk_weights_buffer` | `[tokens][topk]` fp32 | host | DISPATCH |

### 1.2 旗区
- **`local_flags`**（普通显存，`lf`）：`current_time[kGrid][64]`(×512B/block 独立 cache line)、
  `bar[M_CYCLE][1032]`、`out_total/out_processed[kGrid]`、`dbg/ck_dbg`、`pre_ticks[kGrid*16]`、
  `l1_chk/l2_chk[kGrid]`、`exec_ctr`(MX_DBG_COUNT 编译期区分)。
- **`ranks_flags`**（FG/IPC，`rf`）：`xbar_barrier[M_CYCLE][32][32]`(转置布局)、
  `combine_sums[M_CYCLE][topk][512][32]`(epoch 判据)。

### 1.3 计算中间缓冲（普通显存）
- `ffn_hidden`(`d.ffn`)：`[EPR][8][win][I]` FP8，L1 写、L2 读。
- `l2_out`(`d.l2`)：`[kGrid=32][win][H]` BF16，L2 写、COMBINE/融合推送读。
- `frag_a`/`frag2`(OPT-AFRAG)：`[EPR*ring]` 槽，每槽 `(k/32)*mt_total*512`B，L1/L2 A fragment。
- `pool_ptr`：可选独立 pool 缓冲（A-RWK），nullptr 时回落 `sym+pool_off`。
- `y` / `ynode[nodes]`：REDUCE 输出，graph 每节点一份独立缓冲。
- `d_base`/`d_rf`：设备指针表（各 rank sym/rf 基址）。
- 权重 `w1/w2`：lane 序 packed，`fill_weights_lane` 设备侧生成。

### 1.4 SMEM（片上）
- 数据区 `max(window*bn*4, E*4)`（compute_big 中 A-smem 双缓冲 64KB：`2*8*8*512`），L1/L2 共享同一块 smem 取两路较大者；控制区 `(EPR*2+R+2)*4` 及 `s_token/s_task/s_epoch` 等。
- `a_smem/b_smem` 异步分级流水（kBR 级，`bsm` 异步搬运），深流水 kBR*kBatch 在飞块。

## 2. 使用与复用

1. **窗槽滚动复用**：pool/ffn/l2/flag 按 `pool_slot = e*kRing + w%kRing` 索引（ring=8），同一槽 `w` 与 `w+8` 共用；复用由 `l2_done`/`slice_flags`/`l1_prog` 门链串行化（`compute.cuh` §集27/28，`l2_gate_wait` 等待 `(rep+w/ring)*nslice` 达标、`l1_prog` 等待本 slice 完成）。
2. **M_CYCLE=8 轮转**：`bar`、`xbar_barrier`、`combine_sums` 各带 `[M_CYCLE]` 旋转维，本轮只写 `copy c=current_time%8`；入口 `mx_preclear_ct2` 清 `(c+2)%8` 槽，`ct1=(c+1)%8` 本轮绝不碰，完成旗可用常量不清零。`combine_sums` 用单调 epoch 判据（`part < epoch`）免清零。
3. **launch 身份**：`local_flags::current_time[b][0/1]` 单调递增（graph replay 不依赖 host 清零）派生本 launch epoch，xbar release 旗、task_ready 旗、l1_prog 旗均以它为值。
4. **`skip_prologue`(R38)**：同一 graph 内路由不变时，非首节点跳过 ROUTE_BUILD/PUBLISH/XBAR，仅推进 cycle 计数并重跑 TASK_SETUP；`mx_preclear_ct2` 对 xbar 槽跳过清零（epoch 单调保证安全）。
5. **`reset_dev`**（非 graph 路径）：每 launch 前 host memset sym scratch/lf/rf/ffn/l2/combine_rows；graph 模式下靠 epoch/单调计数区分轮次。
6. **combine 迁移**：`combine_sums` 移入 `ranks_flags`（FG），`combine_rows` 数据仍留 sym；COMBINE 推送 = payload(combine_rows 写）→fence→combine_sums epoch 标记；REDUCE 按 `kTopk*nslice_eff` 槽等 combine 完成。
7. **pool/ffn/sym 独立化**：`pool_ptr`(A-RWK)、`ffn`、`l2`、`y/ynode` 从 sym 剥离为独立普通显存，sym 只保留输入视图+scratch+combine_rows。

## 3. 竞争风险

### 3.1 不同 rank 间
- `xbar_barrier` 与任一 rank 的 scratch（ROUTE_BUILD 跨 rank 推送 token 元数据到 dst 的 sym）：**必须**所有 rank launch 次数一致——`current_time` 单调、`c` 同步前进是 M_CYCLE 槽轮转与 epoch 判据的前提。某 rank 掉队/重发则 `c` 错位，可能读到对方上一轮 combine_sums 旧值或覆盖未消费的 combine_rows。
- `combine_sums` 用 `part < epoch` 判据，旧值被当作「未到」，**不需要**预清；但 epoch 由 rank 本地 `current_time` 派生，跨 rank 齐头是契约。REDUCE 等待槽数 = `kTopk*nslice_eff`，`nslice_eff` 广播槽（kBarNsliceEffIdx=1021）错位会漏清。
- `ranks_flags`/`combine_rows` 的 peer 写依赖 `payload → __threadfence() → ready 旗` 顺序；失败时直接表现为数据损坏或 REDUCE 超时（`kCtrReduceTimeout`）。

### 3.2 不同轮次间（同 rank）
- **窗槽复用（已知风险点）**：`pool/ffn/l2` 的 `pool_slot=e*8+w%8` 在 `w` 与 `w+8` 间复用。正确性依赖 `l2_done` ring 门 + `slice_flags`/`l1_prog` 等待；`test/mega_common.cuh` 的自适应窗（`win<slot`）下该链未根治，REDUCE/graph 会失败。当前生产策略强制 `win == slot == max_tokens` 规避，等价于关闭槽间轮次复用的并发收益；**未根治前不得恢复自适应窗**。
- **`bar[c]` 槽轮转**：`M_CYCLE=8` 使同一槽每 8 轮才复用一次，入口预清 ct2 槽，数学上无同轮重叠；但某轮发生超时中断（`dbg` 置错、`kCtr*Timeout`）后，`current_time` 不再齐头，后续 epoch 判据全部失效，需要重置（host 重新 memset/重建 graph）。
- **graph 节点间 `combine_rows`/`l2` 不清零**：节点 k 的 REDUCE 读上一节点留下的 combine_sums 旧值，由 epoch 判据隔离；只要 epoch 单调即安全。`ynode[n]` 每节点独立缓冲，无此问题。
- **`ffn/l2` 按 `(e,w%8)` 在 block 间切分**：任务按 expert/window 划分给 block，不同 block 写不同 slot，同 slot 仅 L1→L2→COMBINE 链式依赖，靠 `l2_done` 门保护 L2 读；`compute.cuh` 注释（[H3]）确认单窗口 rep=0/n_reps=1 时无后续消费者，省略尾 fence 不改变语义。

### 3.3 结论与建议
- 当前无 stride/容量级竞争（slot 索引、容量契约均由 host 断言与 `win==slot` 约束保证）。
- 两个硬约束：**① 全 rank launch 计数齐头**（M_CYCLE/epoch 前提）；**② 窗槽复用处 l2_done/slice/l1_prog 门链完整**（`win==slot` 仅是规避）。
- 建议：bench 中增加跨 rank `current_time` 一致性断言、对 xbar/l2_done/REDUCE 超时即 fail；自适应窗修复后再开放 slot 复用带来的并发。
