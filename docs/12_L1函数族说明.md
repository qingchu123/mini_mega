# 12 L1/L2 函数族：参数模板 / 资源占用 / 适用场景

> 目的：逐条说明 megakernel 里各 **L1/L2** GEMM 变体的模板参数、寄存器/smem 占用、
> 预取深度与理论适用场景；配套测试见 `test/80.l1_func_bench/`（单独跑每个函数）。
> 口径：H=6144、I=2048、topk=8、EPR=8、block_n=256、kNSlice=4、kComputeWarps=8、
> kNTilesPerWarp(kNT)=2、kM=16。
> 对齐提交：`6957f7f`（`[261011_1441]` 尾块 MT 档）——含此前 `[OPT-KCAP-REMOVE]`
> （去编译期 `kCap`、`r24_*_big` 改 `R19_GEMM_ATTR` 隔离）、`[L1TUNE-B/D]`（17..32 改
> `r19<2,1,4>`、49..64 走 r24 掩码）、`[TAIL-MT]`（尾块按精确活跃 tile 选档），
> 选窗为 host 端**自适应**（`win` 逐 launch 定，见 `perf_now.md`）。

## 1. 共同约定

- GEMM：`M=count`（窗口行数）× `N=2I=4096`（L1） × `K=H=6144`；MMA=`16(M)x16(N)x32(K)`。
- tiling：M 按 16（kM）、N 按 16（MMA）/`block_n=256`（组）、K 按 32（kKStep）。
- `MT`=同时处理的 M-tile 数（权重跨 M 复用）；`kBatch`=一次 K 迭代共享 A 的 N 组数；
  `kPrefetch(PF)`/`kBPF`=K 循环预取深度（2 的幂，ring 用 `& (PF-1)` 索引）。
- `acc = Fp8Accumulator[kBatch][MT][kNT]` → **寄存器** `= kBatch*MT*kNT*4` floats。
- `kNT=kNTilesPerWarp=2` 恒成立（layout16b 配对装载要求 `kNTiles==2`）。
- A 来源：行主序 pool、fragment（`fbase`/`f2`），或 r24 的 **A-smem**（由 F 异步搬入）；
  B 来源：global 权重（`ldg` 16B/lane 寄存器预取）。
- 分派几何：`g_l1=(2I/block_n)/nslice_eff`（NS=4→4、NS=8→2）；
  `g_l2=(H/block_n)/nslice_eff`（NS=4→6、NS=8→3）。

**L1**（N=2I=4096，K=H=6144，epilogue=SwiGLU+FP8 量化）

| `r19_l1_big` (compute_big.cuh:346) | `<kMT, kPF, kBatch>` | `kBatch*MT*kNT*4` | 行主序 pool / fragment(fbase) | 寄存器预取环 PF | 小/中档 + 非 async 大档回退 |
| `r24_l1_big` (compute_big.cuh:565) | `<kMT, kKS, kBatch, kMask, kMTAct, kBPF>` | `kBatch*MT*kNT*4` | **A-smem 双缓冲**（bsm 异步） | 直装 ldg，预取环 kBPF | 中大档 async（33..48 / 49..64 / >64 + 尾块） |

## 3. 各函数详解

### 3.1 `l1_gemm_swiglu_body_paired`（遗留 / 微基准）

- **机制**：K 循环按 `kBatch` 个 N 组（gate/up 配对，kBatch 偶数）共享一份 A（`a_pipe`），
  A/B 走**寄存器预取环**（`a_pipe[kPrefetch][kMTiles]`、`b_pair[kPrefetch][kBatch]`）。
  `kUseFrag=true` 时 A 从 fragment（4-line 连续）读，否则行主序 pool（16-line 散射）。
- **现状**：生产分派（`dispatch_pull_body` → `r19_small_task`/`r19_big_task`）**已不再调用**
  该函数；仅 `test/79.l1_gemm_best`、`test/80.l1_func_bench` 隔离微基准使用。
  历史实例：`<2,2,1,4>`/`<2,2,2,4>`（MT1/MT2）、`<2,2,3,4>`（MT3），见 test/80。
- **寄存器**：`<PF,2,MT,4>` → `4*MT*2*4 = 32*MT` floats（MT2→64、MT3→96）。
- **smem**：0（B 只在寄存器）。

### 3.2 `r19_l1_big`

- **机制**：外层 `c0` 按 `kMT*kM`(=kMT*16) 行分组；组内 K 循环外层、M-tile 内层，
  B fragment 在 `kMT` 个 M-tile 间共享（B 每组只读一遍 → 权重遍数
  `= ceil(count/(kMT*16))`）。A 走 `R21_LDA`：`fbase` 非空读 fragment（4 line/指令），
  否则行主序 pool（16 line）。尾组不足由 `r19_load_a` 零填充、写回按 `row<cc` 跳过。
  组对余数（恒偶数）递归 `<kMT,kPF,2>` 收尾。
- **寄存器**：`kBatch*kMT*kNT*4 = 32*kBatch*MT` floats；`<4,2,4>` → 128、
  `<3,2,4>` → 96、`<3,2,2>` → 48、`<1,2,4>` → 32。
- **smem**：0（A/B 都过寄存器）。
- **生产实例**：`<1,2,4>`（≤16,NS4）/`<1,2,2>`（≤16,NS8）、`<2,1,4>`（17..32,NS4）/
  `<4,2,2>`（17..32,NS8）、`<3,2,4>`（33..48,NS4 无 fbase）/`<3,2,2>`（33..48,NS8）、
  兜底 `<4,R19_L1_PF,4>`。
- **场景**：小/中档、无 fragment 或非 async 几何的大档回退。

### 3.3 `r24_l1_big`

- **机制**：A 走 **A-smem 双缓冲**（异步 `__builtin_mxc_ldg_b128_bsm`）；B 走直装
  （`ldg` 16B/lane，预取环 `kBPF`）；每个 stage = `kKS` 个 K step × `kMT` 个 M-tile，
  smem 布局 `[j][m][row][32B]` 与 F_A 逐字一致，LDS 直读 native fragment。
  行区间 `[c0_begin, c0_end)` 分段：整块 `kMask=false` 无掩码快路径 + 尾块
  `kMask=true`（越界 tile 折叠到最后一 tile + `row<cc` 掩码写/checksum）；
  `kMTAct`=尾块活跃 M-tile 数（编译期裁剪 A 搬运/MMA/epilogue）。
- **smem**：`kBufBytes=kMT*kKS*512`，双缓冲 `2*kBufBytes`。生产 `R24_MT=8`、`R24_KS=8`
  → `2*8*8*512 = 64KB`，与 `b_smem` 以 union 折叠（kernel 作用域 `a_smem`）。
- **寄存器**：`kBatch*kMT*kNT*4`；`<8,8,2>` → **128 floats**（顶格）。
- **生产实例**：`<3,16,CM_L1_BATCH,true,3,BPF>`（33..48）、
  `<4,R24_KS,2,false,4,BPF>`（=64 整块）、`<4,R24_KS,2,true,4,BPF>`（49..63 掩码）、
  `<8,R24_KS,2,false,8,kR24BPF>`（>64 全块）、尾块 `kTiny` `<1,16,2,true,1,kR24BPF>`、
  其余 `<8,R24_KS,2,true,l1_act,kR24BPF>`（**l1_act∈2..8 各一档**，[TAIL-MT]）。
- **场景**：有 `fbase` 的中/大档；MT8 把权重遍数减半；A-smem 双缓冲隐藏 A 延迟。

### 3.4 `l2_gemm_body`（compute.cuh:535）

- **机制**：与 `l1_gemm_swiglu_body_paired` 同构（N 组批共享 A 的寄存器预取环），
  但 **L2 = K=I=2048、N=H=6144**，epilogue 为 **BF16** 输出（无 SwiGLU）。
  A=`ffn_hidden`（L1 输出）；`kUseFrag=true` 读 `f2` fragment（4-line），否则行主序。
- **生产实例**：小任务 `<CM_L2_PF,2,1,KB>`（`KB∈{6,4,3,2}` 按 `g_l2` 整除选，
  `g_l2%3==0` 且非 6/4 时 3+3 两批）；大任务 `count≤32` 用 `<CM_L2_PF,2,2,6>` /
  `<2,2,2,3>`（NS=8），`33..48` 用 `<CM_L2_PF,2,3,3>`。
- **寄存器**：`kBatch*MT*kNT*4`；**smem**：0。

### 3.5 `r19_l2_big`（compute_big.cuh:798）

- **机制**：与 `r19_l1_big` 同构（外层 c0 按 `kMT*16` 行分组、B 跨 M-tile 复用），
  K=I、N=H、BF16 输出。**非 async 回退固定 MT4/B3**。
- **生产实例**：只有兜底 `<4, R19_L2_PF, 3>`（`R19_L2_PF=1`）。
- **场景**：无 `f2` 或不满足 async 几何时的 L2 回退。

### 3.6 `r24_l2_big`（compute_big.cuh:835）

- **机制**：与 `r24_l1_big` 同构（A-smem 双缓冲 + B 直装 + `kMask`/`kMTAct`），
  K=I、N=H、BF16 输出；额外支持 **融合推送**（R29，`fuse`，L2 算完一列块即 `__stwt`
  推给目标 rank）。L2 的 `kKS` 同用 `R24_KS=8`（`l1_k_out/32=64` 整除）。
- **smem**：`2*kMT*kKS*512`（与 L1 共享 kernel 作用域 `a_smem`）。
- **生产实例**：`<3,16,3,true,3,kR24BPF>`（33..48）、
  `<4,R24_KS,3,false,4,kR24BPF>`（=64）、`<8,R24_KS,2,false,8,kR24BPF>`（>64 全块）、
  尾块 `<1,16,2,true,1>` / `<8,R24_KS,2,true,l2_act>`（**l2_act∈2..8**，[TAIL-MT]）。

## 4. 任务层分派（谁调用这些 L1）

- `dispatch_pull_body` (compute.cuh:695) 按 `count` 分派：
  - `count <= kM`(16) → `r19_small_task` (compute_big.cuh:1756)；
  - `count >  kM`      → `r19_big_task`   (compute_big.cuh:1327)。
- 两者均 `__noinline__`（`R19_SMALL_ATTR`/`R19_BIG_ATTR`），独立寄存器/栈分配，互不污染。
- `[R31] kSmallOnly` 已删除（无实例化点，恒 false）。
- `[L1L2-SPLIT] kPhase`（`Both`/`L1`/`L2`）里非本节相位由 `if constexpr` 编译期消除
  （`CM_L1L2_SPLIT` 默认 0，即 Both）。
- `[OPT-KCAP-REMOVE]` 已去掉编译期 `kCap`（count 上界）模板参：`mega_kernel`
  只实例化 `<true,false,Both>`（compute）与 `<false,false,Both>`（prelude）。
  原「按 win_cap 选 kCap=48/64 实例删除重档」改由 `r24_*_big` 的
  `R19_GEMM_ATTR=__noinline__` 独立寄存器/栈隔离达成。
- `r24` 系的 B 预取深度 `BPF` 现在**运行期**在调用点按 `S.win_cap` 选：
  `win_cap<=64` → 4，否则 `R24_BPF`(2)（见 compute_big.cuh:1415,1449）；
  常量 `kR24BPF` 已固定为 `R24_BPF`。

## 5. count 档 → 函数映射

> 决策树/图表见 `docs/13_L1选核逻辑.md`。几何 `g_l1=(2I/block_n)/nslice_eff`、
> `g_l2=(H/block_n)/nslice_eff`（block_n=256：NS=4→`g_l1=4,g_l2=6`；NS=8→`2,3`）。

### 5.1 L1

**`r19_small_task`（count≤16）**

| 条件 | L1 |
|---|---|
| `g_l1%4==0`（NS=4） | `r19_l1_big<1,2,4>` |
| 否则（NS=8） | `r19_l1_big<1,2,2>` |

**`r19_big_task`（count>16，compute_big.cuh:1392-1545）**

| count | 条件 | L1 路径 |
|---|---|---|
| 17..32 | `g_l1%4==0` | `r19_l1_big<2,1,4>`（[L1TUNE-B]） |
| 17..32 | `g_l1=2`（NS=8） | `r19_l1_big<4,R19_L1_PF,2>` |
| 33..48 | `g_l1%4==0` 且 `fbase` 且 `(k_in/32)%16==0` | `r24_l1_big<3,16,CM_L1_BATCH,true,3,BPF>` |
| 33..48 | 无 `fbase`/几何不符 | `r19_l1_big<3,2,4>` |
| 33..48 | `g_l1=2`（NS=8） | `r19_l1_big<3,R19_L1_PF,2>` |
| 49..64 | `fbase` 且 `(k_in/32)%R24_KS==0`，且 `count%64==0` | `r24_l1_big<4,R24_KS,2,false,4,BPF>` |
| 49..63 | 同上但非 64 整除 | `r24_l1_big<4,R24_KS,2,true,4,BPF>`（[L1TUNE-D]） |
| >64 | `kAsync`：`fbase` & `count>64` & `(k_in/32)%R24_KS==0` & `g_l1%2==0` | 全块 `r24_l1_big<8,R24_KS,2,false,8,kR24BPF>` |
| >64 尾块 | `count-full<=16` 且 `(k_in/32)%16==0` | `r24_l1_big<1,16,2,true,1,kR24BPF>` |
| >64 尾块 | 其他（`l1_act=ceil((count-full)/16)`） | `r24_l1_big<8,R24_KS,2,true,l1_act,kR24BPF>`（**l1_act∈2..8 各一档**，[TAIL-MT]） |
| 兜底 | 非 async 几何 | `r19_l1_big<4,R19_L1_PF,4>` |

### 5.2 L2

**`r19_small_task`（count≤16，按 `g_l2`）**

| 条件 | L2 |
|---|---|
| `g_l2%6==0`（NS=4：g_l2=6） | `l2_gemm_body<CM_L2_PF,2,1,6>` |
| `g_l2%4==0` | `l2_gemm_body<CM_L2_PF,2,1,4>` |
| `g_l2==3`（NS=8） | `l2_gemm_body<CM_L2_PF,2,1,3>` |
| `g_l2%3==0`（其他 3 倍数） | 3+3 两批 `l2_gemm_body<CM_L2_PF,2,1,3>` |
| 否则 | `l2_gemm_body<4,2,1,2>` |

**`r19_big_task`（count>16，compute_big.cuh:1605-1737）**

| count | 条件 | L2 路径 |
|---|---|---|
| ≤32 | `g_l2%6==0` | `l2_gemm_body<CM_L2_PF,2,2,6>` |
| ≤32 | `g_l2%3==0 && ≥3`（NS=8：g_l2=3） | `l2_gemm_body<2,2,2,3>` |
| 33..48 | `g_l2%6==0` 且 `f2` 且 `(l1_k_out/32)%16==0` | `r24_l2_big<3,16,3,true,3,kR24BPF>` |
| 33..48 | 否则 | `l2_gemm_body<CM_L2_PF,2,3,3>` |
| =64 | `count%64==0` & `f2` & `(l1_k_out/32)%R24_KS==0` | `r24_l2_big<4,R24_KS,3,false,4,kR24BPF>` |
| >64 | `kAsyncL2`：`f2` & `count>64` & `(l1_k_out/32)%R24_KS==0` & `g_l2>=1` | 全块 `r24_l2_big<8,R24_KS,2,false,8,kR24BPF>`（+fuse） |
| >64 尾块 | `count-full<=16`（不同 `(l1_k_out/32)%16` 则退 MT8） | `r24_l2_big<1,16,2,true,1,kR24BPF>`（+fuse） |
| >64 尾块 | 其他（`l2_act∈2..8`） | `r24_l2_big<8,R24_KS,2,true,l2_act,kR24BPF>`（+fuse） |
| 兜底 | 其他 | `r19_l2_big<4,R19_L2_PF,3>` |

> `kAsync`/`kAsyncL2` 门槛 `count>64`，要求 `(k_in/32)%R24_KS==0`（H=6144→192 整除）
> /`(l1_k_out/32)%R24_KS==0`（I=2048→64 整除）；L1 还需 `g_l1%R19_L1_BATCH==0`。
> `>64` 时 `full = count - count%(R19_*_MT*16)`（L1/L2 均 MT8→`count%128`）：若
> `full==count` 只跑全块，否则「全块（无掩码）+ 尾块（`kMask`）」两段式。
> **与 L1 差异**：L2 的 49..63 **未**走 r24（`[L1TUNE-D]` 只改了 L1；L2 该分支仍要求
> `count%64==0`），故 L2 49..63 落 `r19_l2_big<4,1,3>` 回退。
> L1 `BPF`：33..48 与 49..64 档在调用点按 `win_cap<=64 ? 4 : R24_BPF(2)` 运行期选；
> `>64` 用 `kR24BPF(=2)`。

## 6. 理论取舍（为什么这么多）

| 维度 | 小 M（≤16） | 中 M（17..48） | 大 M（>64） |
|---|---|---|---|
| 权重复用 | 不划算（MT1） | MT3/MT4 | MT8 |
| A 装载 | 行主序即可 | fragment 更优 | A-smem 双缓冲（bsm 异步） |
| 寄存器 | 低（acc≤32） | 中（≤128） | 高（128，顶格） |
| 同步/流水 | 简单 | 单批 N | async 两段式 + 尾块掩码 |

- 大 MT/大 kBatch → 权重省、acc 宽、寄存器压力大 → 只在"能摊薄"的大 M 启用。
- 小 M → acc 小、寄存器省，但权重不复用 → 走小档。
- `[OPT-KCAP-REMOVE]` 不再用编译期 `kCap` 裁档；重档寄存器/栈改由
  `R19_GEMM_ATTR=__noinline__` 隔离（见 §4）。
- 隔离微基准（固定 M）**不能**预测真实混合负载最优变体，选型须端到端 A/B（见 §8）。

**结论**：
1. **fragment（frag）恒优于行主序**：−40~44%（如 M=64：172.8 vs 308.8；M=128：345 vs 587）。
   印证 A 走 4-line fragment 的收益（也说明"fbase 恒取 frag"的方向对）。
2. **存在 64→65 的大跳变**（`r24<4,8>` 172.8 → `r24<8,8>` 345.4，≈2×）——即
   `count>64` 进入 async/MT8 路径的台阶（与 docs/11 标定的 `t_task` 跳变一致）。
3. M=17..32 用 `paired<2>`：103~106（frag），M 增大但每档只多付整 tile。

## 8. 交叉扫描与端到端否决（重要教训）

- **隔离扫描**（test/80 的 `r24_full`，循环 c0 覆盖整 M，32 block 同任务）：
  `r24<4,8,4>`（M=65..128 约 310µs）看似优于 `r24<8,8,2>`（约 326µs）。
- **端到端验证**：把 `kAsync` 改为 MT4/B4（caller 循环 c0）后，`win=128` balanced
  TPR256 = **1796 → 1926µs（+7%，更差）**，TPR64 持平。→ **已回退**（`src/compute_big.cuh`
  恢复 MT8/B2）。
- **结论**：**隔离微基准（固定 M、所有 block 做同一任务）不能预测真实混合负载的最优
  L1 变体**（真实是 32 block 各做不同 (expert,window)、寄存器/occupancy/访存相互影响）。
  L1 变体选择必须**端到端** A/B 验证，不能只靠隔离扫描。
- 保留现状：`count>64` 用 `r24<8,8,2>`（MT8/B2）。

## 9. MT16（kBatch=1 两遍）隔离实测否决

- **动机**：MT8 的 `acc = kBatch*MT*kNT*4 = 128` 已顶格；MT16 只能靠 `kBatch=1`（acc=128），
  但 SwiGLU 需 gate/up 配对 → 需重构为「gate/up 各跑一次 K 循环、gate 暂存 smem」。
- **实测**（`test/80`，A 走 smem、K=6144、grid=32、50 次中位，us/launch）：

  | M | `r24<8,8>`（现役） | MT16 kBatch=1 两遍 | 比 |
  |---:|---:|---:|---:|
  | 64 | 241 | 544 | 2.30× |
  | 128 | 345 | 545 | 1.58× |
  | 256 | 668 | 1156 | 1.73× |
  | 384 | 990 | 2249 | 2.27× |
  | 512 | 1313 | 2255 | 1.72× |

- **端到端旁证**（均衡场景 R=32）：朴素把 `R19_L1_MT` 设 16 需 `R24_KS=4`（否则 smem
  131104 > 131072 启动失败），且 `MT16/KS4` 全面回退：win=128 TPR128 1013→4804µs、
  TPR256 1894→4875µs；win=512 TPR512 3685→9583µs。
- **根因**：**A-smem 搬运翻倍**。`r24<8,8,2>` 每趟 K 循环搬 8 tile 供 2 组（gate/up）共享；
  MT16/kBatch=1 每趟搬 16 tile 却只服务 1 组 → 覆盖同样 (16 tile×2 组) 需 **2 趟 = 2× A 流量**，
  外加 2× stage 同步 + gate 的 smem 往返。B 复用翻倍救不回。
- **旁证**：MT8 下单独把 `R24_KS` 8→4（stage/同步翻倍）实测中性（±3%）→「2× 同步」本身非主因，
  **A 流量才是**。
- **结论**：**MT16 经 kBatch=1 重构是净回退，放弃**。在 kBatch=2 约束下 MT=8 仍是 L1 大档最优（acc 顶格 128）。
