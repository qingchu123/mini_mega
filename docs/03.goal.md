# opencode `/goal` 中文使用指南

`/goal` 由 `opencode-goal-plugin` 插件提供，用于给当前**会话**设定一个目标，
让 opencode 在助手每次空闲时**自动继续**，直到目标完成、报告阻塞或触及安全上限后停止。

- 插件版本：`opencode-goal-plugin@0.11.0`
- 依赖：OpenCode 的实验性 hook；请在实际使用的 OpenCode 版本与模型后端上自行验证。

---

## 1. 本仓库的启用方式

插件已在全局配置 `~/.config/opencode/opencode.jsonc` 中注册：

```jsonc
{
  "plugin": [ "opencode-goal-plugin" ],          // OpenCode 2 用 "plugins"
  "command": {
    "goal": {
      "description": "Set a session-scoped goal and auto-continue until complete.",
      "template": "$ARGUMENTS",
      "agent": "build"
    }
  }
}
```

说明：

- **OpenCode 1** 需要上面的 `command.goal` 声明；**OpenCode 2** 插件会自行注册命令，
  此时若还保留 `command.goal` 会**遮蔽**插件处理逻辑，需删除。
- **务必固定版本**：不写版本号时，OpenCode 只在首次安装时解析一次 `@latest`，
  之后即使升级也永远停留在旧版本。升级需改版本号（如 `opencode-goal-plugin@0.11.0`）并重启；
  或删除缓存目录 `~/.cache/opencode/packages/opencode-goal-plugin*` 后重启。

## 2. 基本用法

```text
/goal 修复失败的测试并确认测试套件通过        # 设定目标（替换当前聚焦目标）
/goal status                                  # 查看当前目标与状态
/goal history                                 # 查看生命周期历史与最近检查点
/goal resume                                  # 恢复被暂停/停止的目标（重置预算窗口）
/goal pause                                   # 暂停但保留目标
/goal edit 修复测试，并同步更新文档            # 原地修改目标（保留预算与历史）
/goal clear                                   # 清除本会话所有活动目标
```

别名：`stop` / `off` / `reset` / `none` / `cancel` 等价于 `clear`。

状态行的含义：

- `active`：可继续自动推进。
- `paused`：被用户干预、安全上限或审计拒绝等停止。
- `blocked`：助手记录了具体阻塞原因，需要你介入。

> 目标只属于创建它的会话。子会话 / fork **不会**自动继承父会话目标。

## 3. 单目标参数（flag）

参数支持 `--flag value` 或 `--flag=value`；多词取值需加引号。

```text
/goal 修复测试 --max-turns 20 --max-minutes 30 --max-tokens 400000 --max-cost 5
/goal 发布版本 --success "测试通过且 changelog 已更新" --constraints "不要改动公开 API" --mode ordered
/goal 迁移组件 --budget 150k
```

| 参数 | 作用 |
|---|---|
| `--max-turns <n>` | 自动继续的回合上限 |
| `--max-minutes <n>` | 时长上限（分钟） |
| `--max-duration-ms <n>` | 时长上限（毫秒） |
| `--max-tokens <n>` | 上下文 token 上限 |
| `--budget <n>` | 上下文 token 上限简写，支持 `k`/`m`（如 `100k`、`1.5m`） |
| `--max-cost <n>` | 累计 API 费用上限（美元） |
| `--cooldown-ms <n>` | 两次继续之间的最小延迟 |
| `--success <text>` | 成功判据（别名 `--success-criteria`） |
| `--constraints <text>` | 约束 / 非目标（别名 `--non-goals`） |
| `--mode <normal\|ordered>` | 提示模式；`ordered` 表示在单一目标内保持步骤顺序 |
| `--no-progress-threshold <n>` | 判定“停滞”的输出 token 下限 |
| `--no-progress-turns <n>` | 连续停滞回合数后暂停 |
| `--no-tool-turns <n>` | 连续无工具调用的继续回合数后暂停 |

若目标文本本身包含命令行选项，用 Markdown 代码围栏包裹，围栏内的 `--xxx` 不会被当作参数：

````text
/goal 运行 ```pytest --maxfail=1 --disable-warnings``` 并修复所有失败
````

## 4. 多目标与顺序队列

```text
/goal add 编写迁移指南     # 保留当前目标（转为后台）并聚焦新目标
/goal list                 # 列出编号的活动目标（聚焦 + 后台）及已归档目标
/goal focus 1              # 切换聚焦目标，前一个转入后台
```

- 只有**聚焦**目标会被自动继续，后台目标处于暂停状态。
- `/goal <条件>` 替换聚焦目标；`/goal add <条件>` 新增。

顺序队列（严格流水线，一个完成再自动提升下一个）：

```text
/goal sequence 构建解析器; 编写测试; 发布版本
/goal sequence 构建解析器
编写测试
发布版本
```

`/goal list` 会标记会话为 ordered；序列跑完自动提升停止，`/goal clear` 结束队列。

## 5. 完成标记（助手如何收尾）

助手需在回复**最后一行**给出：

```text
[goal:evidence] 运行 npm test（83 项通过），已核对构建产物
[goal:complete]
```

```text
部署步骤需要我没有的生产 API token。
[goal:blocked]
```

- `[goal:complete]`：仅当其**紧邻的上一行**以 `[goal:evidence]` 开头且包含非空证据摘要时才被接受。
  历史两行格式（先 `[goal:evidence]`，再跟一行证据）也接受；过期或不相邻的标记会被拒绝。
- `[goal:blocked]`：紧邻上一行必须说明**具体阻塞原因**，否则被拒绝并继续工作。
- 方括号形式是规范写法，也接受裸 `goal:complete` / `goal:blocked` / `goal:evidence`。
  自然语言（如 “goal complete”）会被忽略。

无独立审计时，标记质量仍依赖模型自身；可通过审计（见第 9 节）加强。

## 6. 安全上限（默认值）

| 上限 | 默认 |
|---|---|
| 自动继续回合数 | 10 |
| 最长时长 | 15 分钟 |
| 上下文 token | 200,000 |
| API 费用 | 关闭（需设 `maxCostUsd` 或 `--max-cost`） |
| 最小继续间隔 | 1.5 秒 |
| 无进度暂停 | 连续 2 个“停滞”低输出回合后 |
| 预算收尾阈值 | 上下文预算的 80% |
| 连续继续失败暂停 | 3 次 |

- 达到任一上限时，插件会先发一条**收尾提示**（总结已完成 / 待办 / 下一步），而非静默停止。
- 默认 10 回合通常是先于 15 分钟触发的“刹车”；长任务请显式调高。
- `/goal resume` 用全新预算窗口继续同一目标。

## 7. 插件级默认值（全局选项）

在注册插件处传入选项对象即可修改所有目标的默认行为：

```jsonc
{
  "plugin": [
    ["opencode-goal-plugin", {
      "maxTurns": 10,
      "maxDurationMs": 900000,
      "maxTokens": 200000,
      "minDelayMs": 1500,
      "maxCostUsd": 0,
      "noProgressTokenThreshold": 50,
      "noProgressTurnsBeforePause": 2,
      "noToolCallTurnsBeforePause": 2,
      "budgetWrapupRatio": 0.8,
      "maxPromptFailures": 3,
      "persistState": true,
      "stateFilePath": ".opencode/goals/state.json"
    }]
  ]
}
```

常用选项：

- `noInterruptOnUserMessage`：`true` 时，你发送消息不再暂停目标循环（用 `/goal pause` 停止）。
- `noContinueWhileChildrenActive`：`true` 时，子会话（subagent/后台任务）活动期间暂缓自动继续，避免抢占。
- `sessionTitleStatus`：`true` 时把目标状态镜像到会话标题（`▶ 目标 · 3/10 · 2m · 45k/200k`），默认关闭。
- `agentGoalAuthority`：`"full"`（默认）或 `"status"`；后者禁止助手替换/改写/清除目标。
- `registerTools` / `registerAgents` / `registerCommand`：是否注册工具 / 原生 agent / 命令。
- `commandName`：自定义命令名（默认 `goal`）。

## 8. Agent 工具

除 `/goal` 命令外，插件默认注册可调用的模型工具：

- 规范工具：`goal_status`、`goal_set`、`goal_pause`、`goal_resume`、`goal_block`、`goal_complete`，
  返回紧凑的版本化 JSON 信封，便于程序分支判断。
- 兼容别名：`get_goal`、`get_goal_history`、`set_goal`、`update_goal`、`clear_goal`。

`goal_complete` 接受结构化声明：必填非空 `summary`，可选判据/证据对、检查项
（`passed` / `failed` / `not-run`）、改动文件、已知限制。失败的检查项或空的判据证据会在归档前被拒绝。
这些工具与命令路径共享同一套会话多目标状态。

## 9. 完成审计（可选，默认关闭）

默认只有“证据门禁”。可额外要求独立审计后才归档：

- `completionAudit: true`：插件派生独立的子会话来核验完成情况，
  返回 `[audit:approved]` 或 `[audit:rejected]`（附原因）。
- `auditor: async ({ goal, sessionID, latestText }) => ({ approved, reason })`：自定义审计函数。

- 通过 → 归档为已达成。
- 拒绝 → **不归档**，暂停并记录原因 `audit rejected`，可修正后 `/goal resume`。
- 内置/自定义审计默认**失败即拒绝**（fail-closed）。

内置审计器仅做静态检查（`read` / `glob` / `grep`），**不能执行 shell 命令**。

## 10. 持久化与状态文件

- 默认项目本地路径：`<cwd>/.opencode/goals/state.json`（可用 `stateFilePath` 或环境变量
  `OPENCODE_GOAL_STATE_PATH` 覆盖）。
- 每个会话一个哈希分片：`<stateFilePath>.sessions/<sha256(sessionID)>/state.json`，
  同项目不同会话可并发运行。
- 同时维护**追加写**生命周期账本 `<shard>/state.json.ledger.jsonl`；状态文件损坏时由此重建
  仍活动的目标（以**暂停**状态恢复，需 `/goal resume`）。
- 目录为属主专用权限，状态文件 `0600`。建议把 `.opencode/goals/` 加入 `.gitignore`。
- 同一会话同一时刻只允许一个进程持有分片；第二个进程进入**被动模式**（普通聊天可用，
  但 goal 命令/工具报 `session_owned_elsewhere`）。并发工作请 `opencode --continue --fork`。
- `"persistState": false` 可关闭持久化（同时禁用账本），仅内存模式。

---

## 11. 计划模式安全

- 在受限 agent（默认 `["plan"]`）下设定的目标会被**记录但挂起**，停止原因 `plan agent active`，
  自动继续为零，不产生无人值守的工作。
- 切回可执行 agent 后运行 `/goal resume` 开始工作。
- 选项：`restrictedAgents`（默认 `["plan"]`，传 `[]` 解除）、
  `allowGoalExecutionFromPlan`（默认 `false`）。

---

## 12. 注意事项

- OpenCode 自定义命令本质是**提示词**，不是直接渲染的插件输出；可见回复由模型生成，
  可能对插件结果做总结或转述。
- 你手动发消息时，插件视其为最新指令并暂停自动继续，必要时中止已接受的继续请求。
- 命中硬上限的目标会在下次空闲再次暂停；用 `/goal resume` 开启新的预算窗口。
- 跨机器状态不同步；重启后可恢复，但会以暂停态载入以避免盲目自动继续。
